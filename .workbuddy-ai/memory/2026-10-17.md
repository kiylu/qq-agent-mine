# 2026-10-17

## 澄清 L2 的定位 + 修技能页布局

用户问：L2（声明式 Markdown 技能）到底有什么用？是不是给 AI 自己学技能用的？如果不是，
现有项目里好像没太大意义？另外贴了截图说样式有问题。

### 回答要点（已写进 change-plan 的 L2「定位」段）

**L2 本身不是新功能，是 L3 的载体。** L3（续接期后台评审）要产出"以后该怎么做"，
需要一个「能在提示词里被发现 + 不占常驻 token + 人能手工编辑」的容器，就是它。

三型扩展的分工（这个表值得记住）：
| 形态 | 何时生效 | 适合放什么 |
|---|---|---|
| `persona.customRules` / `systemPromptOverride` | 每轮常驻 | 全局、长期稳定的规则 |
| JS 技能 `skills/<id>/index.js` | 模型调工具时 | 需要真正执行动作的能力 |
| Markdown 技能 `SKILL.md` | 命中触发词 / 按需加载 | 场景化的做法（如"怎么主持海龟汤"） |

结论：**没有 L3 时它只能手写，价值有限**（≈"按场景生效的 customRules"）；
**有 L3 时**才是自动沉淀的落点。默认 `enabled: false`，不开时对运行期零影响。

### 布局 bug（截图里左右两栏）

根因：`#view-skills` 是 `display:flex`，`.usage-pane` 是 `flex:1`。
我把 Markdown 区块插成 `#skills-page` 的**兄弟节点** → 变成第二个 flex 列，各占一半。

修法：改成**页内内容**——
- 新增 `loadMarkdownSkillsStatus()` 把数据放进 `state.mdSkills`（与 `state.skills` 同一模式）；
- `loadModulePage('skill')` 先 await 取状态，再 `renderModulePage`；
- `renderModulePage` 里 `const mdHtml = kind === 'skill' ? renderMarkdownSkillsBlock(state.mdSkills) : ''`
  插进 `.usage-wrap`（空态与非空态两个分支都要插）；
- `bindModulePageEvents` 里 `if (kind === 'skill') bindMarkdownSkillsEvents(scope, state.mdSkills)`；
- 渲染用 `h3.usage-h3` + `--bg1/--bd/--r-md` 变量，与既有卡片视觉一致；
- `data === undefined` 时不渲染（避免渲染测试直接调用时显示误导性错误），`null` 才显示"读取失败"。

### 验证

- `render-test` ALL PASSED 95；`coverage-wiring` 5/0；`coverage-ui` 38/1（landing.html 既有失败）。
- `ui/app/06-settings-render.js` 已无 `loadMarkdownSkillsBlock` 残留引用。

## 已实施：L3 自动学习（续接期后台评审）

用户要求加 L3，且**自动学习开关要能在 UI 里改**，不要手改 config。

**新增 `src/auto-review.js`**：
- 触发条件：`autoLearn.enabled` + 不在评审中 + 缓冲存在 + `buf.turns % intervalTurns === 0`。
  用 `turns` 取模而非另起计数器（缓冲里的 turns 就是"本会话第几轮"，不用持久化、不会对不上）。
- 触发点：`orchestrator` 的 `conversation.save()` 之后，且仅 `session.continuation.mode === 'continuation'`。
- 评审**旁路**调用（独立 messages，结果只落盘）；**不复用主会话前缀**——
  主 systemPrompt 是"群友人设"，拿它当前缀模型会继续扮演群友而不是复盘。
- 产出：记忆 → `memory.appendSelf(..., {kind, ownerActive})`（继承 L4b 权重）；
  技能 → `saveMarkdownSkill({..., source:'auto'})`，**手写技能不覆盖**，
  新建受 `createNewSkill` + `maxAutoSkills` 双约束。
- 统计落 `data/auto-learn-stats.json`。

**配置 `config.autoLearn`**：`enabled`(false) / `intervalTurns`(8) / `maxMemories`(2) /
`createNewSkill`(false) / `maxAutoSkills`(10)。

**接口**：`GET /api/auto-learn`、`POST /api/auto-learn/settings`。

**UI**：技能页新增「自动学习（后台评审）」区块（在 Markdown 技能上方）：总开关 / 间隔 /
单次记忆条数 / 允许新建技能 / 自动技能上限 / 已跑次数与上次结果。全在 UI 改。

**两个开关的分工**（容易混，已写进注释+文案）：
- `markdownSkills.allowAutoCreate` = 模型在**聊天中主动**写技能（`remember_skill`）
- `autoLearn.createNewSkill` = **后台定时复盘**时是否允许新建技能

**测试**：新增 `test/auto-review-test.mjs`(20) 挂进 `npm test`；coverage-http 补 2 条路由。
`npm test` 全绿（39 套件）；接口覆盖率 88%（97/110）。

**踩坑**：配置钳制写成 `Number(v) || 默认值` 会吃掉**合法的 0** ——
`maxAutoSkills: 0`（不许自动新建）被替换成 10。已改 `clampInt`（只把非有限数当缺失）。

**剩余未做**：L4a 技能库治理、L4c 全局规则。

## 界面重构：自动学习独立成页签 + 回退技能页改动

用户反馈：① 加在技能页的样式与项目其它地方差异太大；② Markdown 技能本质是"AI 自学习的技能"，
和现有 JS 技能语义不同，应单独起页签；③ 技能页里的改动全部回退。

**回退**：`renderModulePage` 不再拼 `mdHtml`/`autoLearnHtml`；`bindModulePageEvents` 不再绑它们；
技能页恢复原样（旧区块用 `sed` 按行范围精确删除）。

**新页签**：`扩展 → 自动学习`
- `ui/index.html`：`ext-submenu` 加第三项 `data-sub-tab="autolearn"`；
  新增 `<section id="view-autolearn"><div id="autolearn-page" class="usage-pane">`。
- `ui/app/11-init.js`：`initSubmenu('ext-tab','ext-submenu',['skills','plugins','autolearn'])`。
- `ui/app/00-core.js`：`if (name === 'autolearn') loadAutoLearnPage();`（switchTab 按 `view-<name>` 找视图）。
- `ui/app/06-settings-render.js`：`loadAutoLearnPage` / `renderAutoLearnPage` / `buildAutoLearnHtml` /
  `bindAutoLearnPageEvents` + `loadAutoLearnStatus` / `loadMarkdownSkillsStatus`。

**视觉对齐（关键，别再踩）**：

- `.mcard` 默认 `cursor:pointer`，非可点卡片要内联 `cursor:default`。

**测试同步**：
