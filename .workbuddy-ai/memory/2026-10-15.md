Hermes 要点（外部资料，非一手 README）：
- 五层记忆：短期上下文 / MEMORY.md+USER.md（~2200、~1375 字符，满则 consolidate）/ SKILL.md 程序性技能（~/.hermes/skills）/ Honcho 辩证用户建模（存结论不存原文）/ FTS5 全会话检索
- 闭环学习回路：任务后自主写 SKILL.md；触发条件含「≥5 次工具调用」「从错误恢复」「用户纠正」
- 技能遵循 agentskills.io 标准：SKILL.md + YAML frontmatter、**渐进式披露**（元数据常驻、正文按需加载）、条件激活（requires_toolsets / fallback_for_toolsets）、11+ 工具互通
- SOUL.md 人格栈；子代理委派（独立迭代预算）；MCP 双向（client + server 模式）；6 种执行后端；Atropos RL 飞轮（轨迹导出）
- 已知批评（关键）：**无遗忘机制**（不衰减/不剪枝/不检测过期），技能会冲突、用户画像会过时

核心结论（提供给用户的答案主线）：
1. 两个项目押注相反——Hermes「上下文无限增长」vs 本项目「上下文尽量别变」。但 Hermes 的 progressive disclosure 与 `caching-contract.md` 铁律一是同一条原则；可把 Hermes 的自进化机制用本项目的缓存纪律重新实现。
2. 可借（高契合）：① 渐进式披露的技能库（元数据常驻、正文按需追加，自造玩法不破缓存）；② 主动固化 nudge（软重置/定时之外主动持久化）；③ 遗忘/衰减/冲突检测（抄 Hermes 的**教训**，本项目有 consolidation 时机是优势）；④ 后台子上下文隔离重活；⑤ 声明式 Markdown 技能 + 向 agentskills.io 靠；⑥ MCP client→server；⑦ 归档→ShareGPT/SFT 轨迹导出。
3. 别照抄：无遗忘的无限增长记忆、6 后端/HPC/RL 飞轮、多智能体编排、营销叙事。
4. 建议落地顺序：印象 score+衰减+冲突检测（零依赖、最高性价比）→ 声明式 Markdown 技能+渐进式披露 → 主动固化 nudge → 后台子上下文 → MCP/轨迹导出。
