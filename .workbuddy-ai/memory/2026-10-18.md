## 00:15 系统提示词分段编辑 + 人设原地修改

用户两个诉求：① 系统级提示词只能在代码里改，希望透出到 UI；② 人设添加后不能修改，
改了就对不上原来那条、变成独立的自定义人设。

### 1. 系统提示词分段覆盖

- `src/prompt.js` 新增 `PROMPT_SECTIONS`（14 段）/ `promptSectionText()` / `listPromptSections()`；
  `buildSystemPrompt` 改成逐段渲染。**无覆盖时输出与旧版逐字节相同**（段序 + 空行都保持）。
- 覆盖存 `config.promptOverrides = { [sectionId]: text }`，空串 = 恢复默认。
- `security`（安全规则）/ `tools`（工具协议）标 `locked: true`：**config 里写了覆盖也不生效**。
- 路由 `GET/POST /api/prompt-sections`；UI 在设置 → 角色设定 → 「逐段编辑系统提示词」
  （左列选段 / 右侧编辑 / 恢复默认）。

**踩坑（重要）**：`updateConfig` 走 **deepMerge**，`promptOverrides` 里删键会被基底值合回来 →
"恢复默认"失效。改成**写空串**（读取侧 `.trim()` 为空即视为未覆盖）。以后凡是"要能删的
map 型配置"，都只能用空值语义，不能靠删键。

### 2. 人设原地修改

- 根因一：只有 `POST` 新建 / `DELETE` 删除，**没有更新** → 改一次就多一条，原来那条不变。
- 根因二：自定义人设 id 是**数组下标** `custom_${i}`，删中间一条后面全部前移，指向错位。
- 修法：每条自带稳定 `id`（`custom_<base36 时间戳><随机>`），老数据首次读取补一次并写回；
  新增 `PATCH /api/persona-templates/:id`；内置人设只读（400 提示另存为）。
- **同步策略**：保存时若 `persona.roleText === 修改前的 tpl.text`（说明当前正在用这条）→ 一并同步，
  返回 `synced`；已手工改过 roleText 的不动。避免引入 `templateId` 新字段与迁移。
- UI：人设选择弹窗里自定义人设行尾「编辑」（`stopPropagation` 防止触发行选中）。

### 00:25 补：人设编辑入口 + 折叠区间距

用户反馈两点，都是我的实现问题：

1. **找不到人设编辑入口**。当前用的是**内置人设**（小鲸鱼，写在 `personas.js` 里，只读），

   修：设置页「选择人设」行常驻 **「编辑此人设 / 另存为副本」** 按钮，文案随当前人设切换；
   内置（或 roleText 已手改、匹配不到模板）→ 另存为副本（预填当前表单内容，走 POST 新建）。
   `openPersonaEditor(tpl, { prefill })` 新增 prefill：预填内容但走新建。
2. **「整体替换」折叠区间距过大**。`.coll-body` 有 `white-space: pre-wrap`（本是给
   "系统提示 / 工具结果"这类文本用的），把 HTML 缩进当空白保留 → textarea 上下大段空隙。
   改用普通 div + `white-space:normal`，并解掉 `.collapsible` 的 `max-width:86%`（与表单同宽）。

**教训（写进 MEMORY.md）**：`.coll-body` 是"保留换行"的**文本容器**，不要用来包表单控件。

### 00:30 修：编辑人设不带入旧内容

用户反馈"编辑没带入以前写好的人设，得从头写"。两处根因：

1. **`loadSettings` 缓存丢字段**（`05-memory-settings.js:649`）：往 `state.personaTemplates`
   里存模板时只写了 `{ name, text, builtin }`，**漏了 `customRules`** —— 于是"编辑此人设"
   打开后附加规则永远是空的。
2. **「另存为副本」只读 DOM**（`$('#cfg-roletext')`）：分会话模式或元素不在当前渲染分支时
   拿到空串，弹窗就是空白。

修法：
- 缓存补上 `customRules`。
- 取值改**三层兜底**：输入框（可能刚改过）→ `state.config.persona.roleText/customRules` → 模板原文。
- `openPersonaEditor` 内部对正文再做一次同样的兜底，避免调用方传空。

**教训**：前端"缓存模板对象"时要把弹窗用到的字段全带上；只读 DOM 取当前值不可靠，
配置（`state.config`）才是稳定来源。

### 00:45 人设编辑彻底修：改用 templateId，不再文本比对

用户反馈三连：编辑按钮"一会有一会没有"、要先去角色设定敲几个字才认得出、点进去只能另存为。
根因是**同一个**：判断"当前是哪个模板"靠 `roleText` 文本比对。

具体三处：
1. `state.personaTemplates` 缓存里**连 `id` 都没存**（只存 name/text/builtin）→
   `openPersonaEditor` 的 `isEdit = Boolean(tpl.id && ...)` 恒为 false → **只能新建**。
   （这是"点编辑只能另存为"的直接原因）
2. `currentPersonaId()` 靠 `roleText === p.text` 比对 → 用户改一个字就返回 ''，
   按钮文案/删除按钮随之消失；输入触发 input 才重新 sync → "得敲几个字才带入"。
3. 按钮文案在「编辑此人设 / 另存为副本」之间切换 → 观感上"按钮一会有一会没有"。

修法：
- `config.persona.templateId` 显式记录来源；`#cfg-persona-pick` 用 `dataset.templateId` 携带，
  `saveConfig` 的 persona patch 落盘。老数据没有该字段时才退回文本比对。
- `state.personaTemplates` 缓存补 `id` + `customRules`。
- 按钮文案固定「编辑人设」，行为在点击时按 id 决定（custom_ → PATCH；否则另存为）。
- 编辑正文用**当前角色设定**（改了什么存什么），不是模板原文。
- 新建/另存为成功后立刻 `dataset.templateId = savedId` 并同步 `state.config`（防 loadSettings 用旧值覆盖）。
- 删除后回落到 `xiaojingyu` 并改 dataset，避免把已删 id 写回配置。
- 分会话弹窗（`openPerChatPersonaModal`）补「编辑人设」；`openPersonaEditor` 加 `onSaved` 回调，
  分会话保存后回填自己的输入框（它不在设置页表单里）。

**教训**：**"当前选中了哪个对象"要用 id 显式记录，绝不能靠内容比对**。
内容比对会把"用户编辑过内容"误判成"没选中任何对象"，而且依赖 DOM 当前值，时序上很脆。
