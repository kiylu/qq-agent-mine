## 这个版本主要改了什么

### 1. 会话不再「用完即弃」，机器人自己的思考能跨轮留下来

上游的做法是**每次触发都新开一个会话、处理完就丢**，LLM 层面零历史。好处是单次成本恒定，
  
代价是机器人**上一轮想过什么，这一轮完全不知道**——像海龟汤、长任务、打赌这类要「自己心里有数」的玩法基本没法用。

这个版本改成：**连续对话就接着上一轮往下走**。两条消息间隔没超过沉默阈值时，直接在上一轮的上下文里追加新内容，
  
机器人自己的思考链天然就留在里面了，不用重新注入、也不用多花一份钱。
  
真沉默够久（或者人设、可用工具变了）才关掉重开，重新起一段。

沉默阈值按**模型渠道**自动取——各家缓存能留多久不一样，取「缓存还没过期」的那个长度：

- 多数渠道（含中转站）：5 分钟上下
- Anthropic：4 分钟
- OpenAI 系：8 分钟
- DeepSeek / Gemini：这两家缓存留得久，给到 60 分钟

顺带一个必须说清楚的后果：***成本模型变了****。原来是「每次固定一小份」，现在是「****上下文有界增长、单价靠缓存压住****」——
  
聊得越久上下文越长，但有轮次和体积两道上限兜底，撑不住就自动软重置；重复的那部分按缓存价算，
  
所以只要缓存还在命中，长上下文并没有看起来那么贵。用量页能直接看到实际命中率。*

### 2. 历史图片不再每轮重复计费

连续对话中间看过的图片、视频，会被换成一行文字占位，避免图片 token 每一轮都重新传一遍。
  
代价是切换那一刻会丢一次缓存，所以做成了可关的开关，默认开着（多数场景更划算）。

### 3. 关掉的会话可以回溯

会话关闭或手动重开时，会先归档一份再清空，每个会话保留最近若干段。
  
存档页上能看到「已归档 N 段会话」，方便排查问题。

### 4. 提示词按「变化频率」重排，缓存命中率抬起来

成本优势完全建立在「前缀不变」上，所以提示词的段落顺序按**会不会自己变**重新排了：
  
会随手变化的那些内容（记忆、可用表情包列表）不再排在前面，免得写一条新印象、发一次表情，
  
就把后面最大的一块上下文全部踢出缓存。另外发给模型的历史响应体也剥掉了，不再重复上传。

### 5. 思考强度和思维链

- **思考强度**给了明确档位（默认 / 关闭 / 低 / 中 / 高 / 更高 / 最高），按渠道自动换算成对方认识的档位。
    
  这里原先有个**静默失效**的毛病：DeepSeek 和 GLM 渠道下，选什么档都等于没选，实际一直停在默认档
    
  （设置显示已保存、请求也确实发了，就是强度没变）。现已修好——设置里显示什么，发出去就是什么。
- 界面上能直接看到**每次会话的思维链**和**这一次的缓存命中率**，不用再靠猜「到底命中了没有」。

### 6. 优化模型供应商管理

多个中转站、多个 Key 可以分开管理，每个供应商能写备注，列表和选择器显示一致。
  

### 7. 扩展（技能 / 插件）加了「缓存体检」

两型扩展的机制沿用了上游。这个版本在扩展页上加了一个**体检**：会主动标出「每轮都会变的内容」
  
（比如往系统提示里塞动态文本的扩展）。因为这类扩展**不报错、不崩、就是没反应**，但会让会话每轮被迫重开、


### 8. 界面调整

顶栏收敛成 **会话 / 记录 / 用量 / 扩展 / SnowLuma / 设置**：存档和记忆收进「记录」，技能和插件收进「扩展」。

- 会话详情加了**状态徽标**——「续用第 N 轮」/「新开会话 + 原因」，排障时不用再翻日志；
- 存档页加了「重开会话」和「重开并蒸馏」两个入口（都带二次确认）；
- 活跃度概率支持手动输入；顺手清掉了一些彩蛋和冗余入口。

## 安装与使用

### 三步搞定（推荐）

```bash
git clone https://github.com/kiylu/qq-agent-mine.git
cd qq-agent-mine
npm install
npm run setup        # 自动下载 SnowLuma + 固定版本便携 QQ（幂等，可重复执行）
```

然后双击 `启动QQ机器人.bat`（或 `npm start`），在 SnowLuma 页签点「启动 QQ」，扫码登录即可。
  
进设置页 —— 顶部体检卡会告诉你缺什么：填接口地址和 Key → 选模型 → 勾白名单。

### 手动安装（`npm run setup` 下载失败时）

1. **装协议端**：SnowLuma 是独立第三方项目（自带 EULA，不随本仓库分发），从其官方渠道获取后
     
   解压到项目根目录，目录名保持 `snowluma`。
2. **装便携 QQ**（可选，二选一）：
   - **最省事**：机器上已经装过 QQ → **先完全退出 QQ**，直接跑 `npm run setup`，
       
     脚本会从注册表找到已装的 QQ 并复制一份（约 1.6 GB，自动跳过聊天记录）；
   - **或**按脚本提示的地址下载安装包，**正常双击安装一遍**，再退出 QQ、重跑 `npm run setup`。
       
     QQ 9.9.x 用的是腾讯自研的 **HummerSetup** 安装器，不接受静默安装参数，
       
     脚本会识别出来并说明，而不是盲试到超时。
3. **启动**：双击 `启动QQ机器人.bat`（或 `npm start`），扫码登录 QQ。

### 关于 QQ 便携包从哪来

`npm run setup` 会下载两样东西：**SnowLuma**（从它的 GitHub Release 拉固定版本）和 **QQ 便携包**。
  
后者目前仍指向**上游作者的分发站**，所以如果那个站不可用（没网、地址失效、清档），有两条替代路径：

- **自己打包一份**：`npm run pack:qq` 能把本机的便携 QQ 打成归档，脚本会打印出校验值和两行配置，
    
  填进去换掉下载地址即可；
- **干脆不用便携包**：完全退出 QQ 后跑 `npm run setup -- --no-portable`，
    
  或者用 `--from "D:\你装到哪"` 指定目录，脚本会从本机已装的 QQ 复制一份。

脚本选来源时按「指定目录 → 版本匹配的那份 → 读不到版本的 → 版本不符的（会警告）」的顺序来，
  
**不会随手拿第一个**——机器上同时有 QQ 9.7 和 9.9 时，拿错版本会表现为登录失败，很容易查错方向。

> 便携 QQ 用的是自己独立的数据目录，和你日常用的 QQ 完全隔离；关闭时也只杀自己那一份进程，
>   
> 不会碰你已登录的 QQ。**换 QQ 版本前先看这里**：登录被拒或接口行为异常时，优先怀疑版本不匹配，
>   
> 而不是网络或账号。

### 开发 / 测试命令

```bash
npm install          # 装依赖
npm run setup        # 一键下载 SnowLuma + 便携 QQ（幂等）
npm run setup:check  # 只检查是否已就绪
npm start            # 桌面端启动
npm run server       # headless 模式：浏览器打开 http://127.0.0.1:3210
npm test             # 全量测试（36 个套件）
npm run test:coverage # 覆盖测试（模块层 + 全部 HTTP 接口 + 端到端链路 + 静态界面层）
npm run test:all     # 两套一起跑
```

> 界面接线检查依赖 jsdom，但它不是本项目的依赖 —— 没装时会打印提示并**自动跳过**，不影响其它套件。

## 升级与回滚（覆盖式，数据不丢）

**发布包里从来不含 `data/`，所以「覆盖」永远不会碰到你的聊天记录、记忆、Key 与登录态。**

1. **先完全退出 QQ Agent**（含托盘，以及后台的 SnowLuma / QQ 进程）；
2. **备份 `data/`**：`cp -r data data.bak-$(date +%Y%m%d)`；
3. 解压新发布包，把内容**合并覆盖**到原项目目录（选「替换目标中的文件」，
     
   **不要清空目录再解压**，`data/` 就天然被保留）；
4. 若用的是精简包，补一次 `npm install && npm run setup`；完整包解压即用；
5. **启动验证**：`启动QQ机器人.bat`，首次启动会自动补齐新版引入的默认配置。

新旧版本对配置和存档一律是「缺的字段补默认值、废弃字段安全剔除、坏文件先备份再回落默认」，
  
所以**覆盖只动了代码、没动数据，回滚同样无损**。
