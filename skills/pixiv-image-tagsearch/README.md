# Pixiv 来张图（标签检索）

> 这是「标签检索」变体：取图流程与原版一致，区别是**设了最低收藏数时会优先走 Pixiv 的「N users入り」约定标签**去捞攒够收藏的作品。两个技能共用同一份 PID 索引与图库（都在数据目录的 `pixiv/` 下），所以同一张作品不会被两个技能各发一次。

群友说「**来张 恋恋**」，机器人就从 Pixiv 找一张符合角色标签的插画发进群，并附上标题、作者、收藏量。

和常见的「关键词搜图」不同，这个技能是**按角色标签**搜 Pixiv 插画的，而且**记得自己爬过什么**——同一个作品不会被反复发出来。

---

## 它解决什么问题

大多数搜图机器人的通病是：搜到的图翻来覆去就那几张，因为每次都是从搜索结果里随机挑，没有任何"发过什么"的记忆。爬几次把候选耗尽之后，还会直接报"没找到图"。

这个技能把「爬过什么」记成一份 **PID 索引**：

- 挑选候选**之前**就按作品 ID 把爬过的剔掉 —— 保证每次给的尽量是新图
- 新图真的翻完了，会明说「这些是以前存过的」并复用本地文件，**而不是报失败**
- 索引里连作者、标题、收藏量一起存了，以后回答"这张谁画的"不用再联网

## 特性

| 特性 | 说明 |
|---|---|
| **PID 索引去重** | 原子写盘的 `pid-index.json`，O(1) 查询。断电不会毁掉整个索引 |
| **迁移友好** | 目录扫描兜底：从别的机器人搬过来的图库，靠文件名 hash 后缀也能识别为"已入库" |
| **附带作品信息** | 发图后补一条：标题、作者、收藏/点赞/浏览、作品号。可关 |
| **标签词典自学习** | 模型填一次日文标签就永久记住，下次零成本；也支持导入你既有的中→日映射表 |
| **代理保活** | 端口没开时可自动后台拉起 sing-box 核心（默认关），带 60 秒节流和并发锁 |
| **候选耗尽降级** | 不会因为"都爬过了"而空手而归 |
| **代理不可用早报错** | 区分"代理没开"和"搜索失败"，给出可执行的提示 |

## 装之前你需要知道

1. **必须能访问 Pixiv**。国内需要自备代理，本技能不提供节点。默认按 v2rayN 的常见配置 `socks5h://127.0.0.1:10808` 预设，可在设置里改。
2. **依赖 `curl.exe`**。Windows 10 1803 及以上系统自带，无需安装。
   （为什么不用内置的网络请求：Node 的 undici 不支持 socks5 代理，而 Pixiv 场景基本必须走 socks5。）
3. **需要一个能看图、能写信的模型**——不需要视觉能力，本技能不分析图片内容，只按标签搜索。

## 使用

对机器人说下面任意一句（群里需要 @ 它）：

```
来张 古明地恋
来一张 博丽灵梦
给我来张 琪露诺
找张 芙兰朵露
```

**日文标签由模型自动补全**。模型认识东方角色，会在调用时一并给出该角色的 Pixiv 日文标签（例如 古明地恋 → 古明地こいし），技能把这个映射记进词典，之后同一个角色就是零成本。你也可以在设置里导入已有的映射表。

一次最多发 3 张（`count` 参数）。

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `apiBase` | `https://www.pixiv.net` | 接口域名，换镜像站时改 |
| `proxy` | `socks5h://127.0.0.1:10808` | 代理地址，留空 = 直连 |
| `autoStartProxy` | 关 | 端口没开时后台静默拉起 sing-box |
| `proxyCoreDir` | 空 | v2rayN 目录（仅自动拉起时需要） |
| `legacyTagDict` | 空 | 外部的「中文→日文 tag」映射表路径，首次运行导入 |
| `imageDir` | 空 | 图库目录。留空 = 存在程序数据目录下，随数据备份 |
| `showInfo` | 开 | 发图后附带作品信息 |
| `minBookmarks` | 1000 | 最低收藏数，0 = 不限。设了门槛就优先用「N users入り」约定标签检索，再按真实收藏数复核 |
| `strictMinBookmarks` | 关 | **v1.1.0 新增**。关：候选都不达标时放宽门槛照发（并在消息里标注）；开：一个都不达标就不发图，改为说明「翻了几个候选、最高多少收藏」 |
| `usePopularTag` | 开 | **v1.1.0 新增**。用 Pixiv 的「N users入り」约定标签找高收藏作品，不够时自动回落到普通标签 |
| `candidatePages` | 3 | 搜索翻页数，**1~10**（v1.1.0 起上限从 3 放宽）。设了收藏门槛时它才真正起作用 |
| `skipMultiPage` | 开 | 只爬单张插图，排除多页图集 |
| `mode` | `safe` | `safe` 全年龄 / `all` 含 R18 |
| `type` | `artwork` | `artwork` 只插画 / `all` 含漫画 |
| `timeoutMs` | 25000 | 单次 Pixiv 请求超时（毫秒） |

## 数据存在哪

都放在 QQ Agent 数据目录的 `pixiv/` 子目录下：

```
pixiv/
  pid-index.json    爬过的作品索引 {pid: {file, folder, tags, author, title, ...}}
  tag-dict.json     中/英 → 日文标签映射
  images/<角色>/    下载的图片（imageDir 留空时）
```

删掉 `pid-index.json` 相当于"忘记爬过什么"，之后会重新爬重复的图。

## 已知的限制

- **图集只取一页**。开启 `skipMultiPage` 时直接跳过图集；关闭时随机抽一页，抽到的那页未必符合搜索标签。
- **标签命中率取决于模型给的对不对**。给错了日文标签就搜不到，此时换个说法或手动指定标签。
- **不分析图片内容**。它只按标签搜，不判断图里画的是不是你要的角色。
- **`curl.exe` 版本过老可能影响 TLS**。Windows 自带的 7.55 实测可用；如果报 TLS 相关错误，考虑装新版 curl。
- **「users入り」标签靠上传者自觉**。它只是 Pixiv 上的民间约定，偶尔有人乱打，所以最终仍会按真实收藏数复核；门槛设得越高，越可能"翻遍候选也没有达标的"。

## 更新记录

### v1.1.0 —— 让「最低收藏数」真正生效

修的是"设了收藏门槛、却照发低收藏作品"的问题。原因有三层，前两层是代码里的坑，第三层是 Pixiv 自己的限制：

1. **候选池写死 24 个**：只取搜索结果里最新的 24 个作品去比收藏，于是「搜索翻页数」调到 5 也毫无作用（第 1 页就填满了）。→ 现在候选上限跟随翻页数（最多 120 个），并且"达标候选够挑了"就提前收工，不会无脑翻到底。
2. **翻页数被静默夹到 3**：`Math.min(3, ...)`，填 5 实际按 3 跑。→ 上限放宽到 10。
3. **Pixiv 搜索接口在未登录时只提供"最新优先"**：`order=popular_d`（按热度）与 `blt`（收藏数筛选）参数**会被直接忽略**（实测五种写法返回同一批结果），所以"最新的一两百个作品"收藏根本还没攒起来——实测翻 5 页 142 个候选，最高只有 444。→ 改用上传者自己打的**「N users入り」约定标签**（实测「初音ミク 500users入り」前 5 个作品收藏 754 / 881 / 775 / 531 / 839，「1000users入り」前 5 个 5818 / 1263 / 1331 / 1860 / 1023），设了门槛就优先走这条路，不够再回落普通标签。

另外：**一旦放宽门槛，会在群消息、工具结果和日志里同时标注**，不再静默发出低于门槛的图。（旧实现的设置说明里确实写了"会自动放宽"，但没人会在用之前去读那一行。）
