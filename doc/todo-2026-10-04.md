## 决策记录：为什么不改 API 方言

曾讨论"改成 Anthropic Messages / OpenAI Responses 形态以获得思考连续性"，**结论是不改**。

| 变量 | 影响 |
|---|---|
| 换 API 方言 | 只提升**工具轮内**推理连贯性（回传通道从无→有） |
| 换模型 | **这才是"变聪明"的来源**（thinking on/off：AIME 23%→61%、MATH 82%→96%） |

本项目实测：**平均 2.00 轮 API 调用 / 2.08 次工具调用 / 12256 字符提示词**
（12 份会话存档统计）—— 轮次极少、工具极少，正是 reasoning continuity 收益最小的场景。

**结论：想变聪明应该换模型，不是换方言。** 方言改造是纯工程成本换不到对应收益。

## Q4 详查：确认是 bug（2026-10-04 17:01 查实）

**结论：DeepSeek / GLM 渠道下，设置页的六档 thinking 全部无效，实际永远是默认 high。**

### 证据

`src/thinking.js:186-191`：
```js
case 'deepseek':
case 'glm': {
  if (on) { params.thinking = { type: 'enabled' }; applied = true; omitTemperature = true; }
  else if (e === 'off') { params.thinking = { type: 'disabled' }; applied = true; }
  break;   // ← 没有任何 effort 字段
}
```
`grep -rn "reasoning_effort" src/ ui/` 全部命中仅 4 处，**deepseek 分支一处都没有**：
`:70`/`:114`/`:255` 是注释与常量表，`:199-200` 属 **openai-o**、`:204` 属 **xai**。

而 DeepSeek 官方文档明确 effort 是**独立参数**：

| 格式 | 开关 | 强度 |
|---|---|---|
| OpenAI | `{"thinking":{"type":"enabled/disabled"}}` | `{"reasoning_effort":"low/high/max"}` |
| Anthropic | `{"reasoning":{"effort":"none/low/high/max"}}` | 同左 |

**UI 侧确实暴露了六档**（`06-settings-render.js:840-846`）：
`off / '' / on-noeffort / low / medium / high / xhigh / max`
—— 用户在 DeepSeek 渠道选"低（快、省 token）"，**实际发出的仍是
`{"thinking":{"type":"enabled"}}`（默认 high）**。
这是**静默失效**：设置显示已保存、参数确实发出、但强度完全没变。

### 修法（未实施）

```js
if (on) {
  params.thinking = { type: 'enabled' };
  params.reasoning_effort = eff || 'high';   // ← 补这行；复用 :183 的就近映射
  applied = true; omitTemperature = true;
}
```
⚠️ `xhigh` 不在 DeepSeek 合法值里（只认 low/high/max），需复用 `:183` 的
`OPENAI_EFFORTS` 映射。另：`THINKING_BODY_KEYS` 已含 `reasoning_effort`，
降级重试会自动摘掉，**无需额外改**。

### 需要用户提供 JSON 记录吗？——**不需要**

Q4 是"发出的请求体缺字段"，**读代码即可定论**。
那份运行期 JSON 能提供的是**佐证**（`raw` 里能看到服务端实际返回的
`reasoning_content` 长度与 `usage.completion_tokens_details.reasoning_tokens`），
不是判据。**只有在验证修复效果时**才需要"修复前/后"两份对比数据。
