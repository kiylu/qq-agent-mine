# 系统提示词分段编辑 + 人设原地修改（2026-10-18）

## 1. 系统提示词：从"只能改代码"到"逐段可编辑"

**怎么改**

- `src/prompt.js`：新增 `PROMPT_SECTIONS`（14 段）、`promptSectionText()`、`listPromptSections()`；
  `buildSystemPrompt` 改为逐段渲染。**无覆盖时输出与旧版逐字节相同**（段序、空行分隔都保持原样）。
- `config.promptOverrides = { [sectionId]: '替换文本' }`，空串 = 恢复默认。
- 路由：`GET /api/prompt-sections`（列默认值/覆盖值/生效值）、`POST /api/prompt-sections`（保存）。
- UI：设置 → 角色设定 → 「逐段编辑系统提示词」——左列选段，右侧编辑生效文本，带「恢复默认」。

**分段清单**

| id | 标题 | 可覆盖 |
|---|---|---|
| intro | 开场身份 | ✓ |
| security | 安全规则 | ✗ 锁定 |

**效果**：改"反 AI 味""表情包策略""引用规则"这类行为段，不用改代码、不用重启；
只替换单段，其余保持默认 —— 比原来的 `systemPromptOverride`（整体替换）安全得多。

**负面效果**：覆盖内容质量由用户负责，写坏了直接影响行为（有「恢复默认」可一键退回）；
改动在**下一个会话**生效（会话内提示词逐字节复用，不打断缓存）。

## 2. 人设：可以原地修改

**原来的问题**

- 只有 `POST`（新建）/ `DELETE`（删除），**没有更新**：想改一条已有人设只能再建一条，
  模板库里原来那条纹丝不动 → "改完就对不上原本添加的那个人设"。
- 自定义人设的 id 是**数组下标**（`custom_0`）：删掉中间一条，后面所有 id 前移，指向会错位。

**怎么改**

- 每条自定义人设自带 `id`（`custom_<base36 时间戳><随机>`）；老数据首次读取时补一次并写回 config。
- 新增 `PATCH /api/persona-templates/:id`：原地改 name / text / customRules，**不产生副本**。
- 内置人设只读（写在 `personas.js` 里），PATCH 返回 400 并提示"另存为自定义人设"。
- 新增 `persona.templateId`：显式记录"当前人设来自哪条模板"。
  **不再用 roleText 文本比对** —— 用户改一个字就匹配不到，表现为编辑/删除按钮莫名消失、
  「编辑」退化成「另存为」、必须先在角色设定里敲几个字才认得出。
- 前端模板缓存 `state.personaTemplates` 必须带 **`id` 与 `customRules`**：
  少了 `id`，编辑器判断不出"这是编辑"，只能走新建（这正是"点编辑只能另存为"的直接原因）。

**UI**

- 设置页「选择人设」行常驻 **「编辑人设」** 按钮，文案固定不跳；行为按来源决定：
  - 自定义 → 原地改（PATCH）。正文预填**当前角色设定**，改了什么就存什么。
  - 内置 / 手写内容 → 另存为副本（弹窗标题写明"另存为新人设"）。
- 人设选择弹窗里，自定义人设行尾也有「编辑」。
- 分会话人设弹窗（关掉"统一人设"后，在「人设」页点某个会话的编辑）也加了「编辑人设」，
  保存后回填到该会话的角色设定。

**效果**：新建的自定义人设立刻可编辑；改内容不再丢失"我是哪条人设"的身份。

**负面效果**：`templateId` 记录的是"选过哪条"，用户手工改 roleText 后仍指向原模板 ——
此时点「编辑人设」会把当前内容存回该模板（符合"改了什么存什么"，但等于覆盖原模板）。

## 3. UI 修正

- 「整体替换」折叠区不再用 `.coll-body`：该类有 `white-space: pre-wrap`（本是给"系统提示 /
  工具结果"用的），会把 HTML 缩进当成空白保留，textarea 上下出现大段空隙。
  改用普通 div（`white-space: normal`），并解掉 `.collapsible` 的 `max-width: 86%`，与表单同宽。
- 设置页「系统提示词覆盖」的说明原本写"安全规则、工具协议全部失效"，**与代码不符**
  （`buildSystemPrompt` 的 override 分支始终追加这两段）。已改正；整块收进折叠区，
  主入口换成「逐段编辑」。

## 缓存影响

- 无覆盖时系统提示词**逐字节不变**，升级后不会 fresh。
- 一旦保存了覆盖 → 字节变化 → 下一个会话 fresh 一次，之后照常命中。
- `config.promptOverrides` 只读、不掺时间戳/随机数，会话内稳定。
